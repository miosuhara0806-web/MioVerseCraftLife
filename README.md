# MioVerse 小径の工房

採集 → 加工 → 住人への納品を試す、戦闘・時間制限のない生活ゲームの試作版です。

## 遊び方

`index.html` をブラウザで開きます。スマホや GitHub Pages では、`index.html`・`style.css`・`game.js`・`app.js` を同じフォルダで配信してください。ビルド・依存パッケージ・外部通信は不要です。

1. 採集で枝・ツル草・野花を選びます。毎回2個、1日3回まで採集できます。
2. 加工で素材を消費して次の品物をつくります。1個ずつ、または素材を使ってまとめて加工できます。
3. 依頼で布袋・染料・小箱を各1個納品します。依頼は各1回限り、達成後も採集と加工は続けられます。
4. 最初の3件をすべて納品すると、第2段階の3件（カーテン・壁掛け・染め布）が解放されます。こちらも「1個届ける」で手動納品します。最初の3件のお礼は引き続き読み返せます。

最初の布袋：ツル草を1回採集 → 植物繊維2個 → 糸2個 → 布1個 → 布袋1個 → ナカちゃんへ納品。
小箱：枝を2回採集 → 木材2個 → 板材2個 → 小箱1個。
染料：野花を1回採集 → 乾燥花2個 → 染料1個。

加工画面の「組み合わせのしごと」に追加したレシピ：

- 布1個 ＋ 染料1個 → 染め布1個
- 染め布2個 ＋ 糸1個 → カーテン1個
- 板材1個 ＋ 染め布1個 → 壁掛け1個

複数素材のうち一つでも不足していれば加工できず、他の素材も消費しません。「まとめて」は全素材から作れる最大数を使います。染め布は中間素材、カーテン・壁掛けは完成品の棚に表示されます。追加レシピは最初から利用でき、追加依頼のみ段階解放されます。

## 第3段階：素材の使い道を増やす

最初の6件をすべて手動納品すると、花のリース・クッション・布張り小箱の依頼3件が解放されます。全9件とも作成だけでは達成せず、納品時に1個消費します。

- ツル草2個 ＋ 乾燥花2個 ＋ 糸1個 → 花のリース1個
- 小箱1個 ＋ 染め布1個 → 布張り小箱1個
- 染め布2個 ＋ 植物繊維2個 ＋ 糸1個 → クッション1個

新しい3品は完成品の棚に表示されます。レシピは最初から利用できます。乾燥花を染料にするかリースにするか、小箱を納品するか追加加工するかを選べます。
旧セーブの在庫・達成状況を保持し、6件達成済みなら第3段階を解放します。新在庫は0から開始します。解放段階は各段階より前の依頼の達成状況から復元し、在庫・達成状況とともに保存します。

## 日常依頼

固定依頼9件をすべて納品すると、ナカちゃん・律さん・秘書トワ・軽快トワ・シル・黒子・アルト・碧博士の日常依頼から、合計3件が届きます。45件の専用プールから既存レシピと家具レシピだけを使って抽選し、同日の依頼重複と直前の同枠再登場を避けます。

日常依頼も完成品を作っただけでは達成になりません。依頼画面で手動納品すると指定数を在庫から消費し、その日は「お届け済み」になります。未達成の依頼は翌日へ持ち越し、お届け済みの枠だけが「今日は休む」で次の日になった際に入れ替わります。期限・失敗ペナルティはありません。

現在の3枠、各枠の達成状態、直近の抽選履歴は既存の保存キーに追加して保存します。9件達成済みの旧セーブには初回の3件だけを安全に補い、在庫・日数など既存の進行は初期化しません。

## 図鑑

図鑑には現在の全21種類を表示します。未発見品は名前や作り方を伏せ、一度でも採集・加工した品は在庫が0になっても発見済みとして残ります。発見済み品は現在の在庫と、レシピがあれば必要素材を確認できます。旧セーブで18種類を発見済みでも、新しい家具3種類は制作するまで未発見です。

発見状態は従来の保存キー内の `discovered` に記録します。旧セーブでこの項目がない場合だけ、在庫と納品済み依頼からレシピを再帰的にたどって過去の発見を推定し、その結果を保存します。未達成の日常依頼や抽選履歴だけでは入手済みとは判定しません。

## 家具のしごと

加工画面の「家具のしごと」で、板材2個から木枠1個、木枠1個と板材2個から小さな棚1個、木枠1個・染め布1個・植物繊維1個から布張りスツール1個を作れます。木枠は加工素材、棚とスツールは完成品です。家具の配置機能はありません。

家具を求める日常依頼5件は、既存の依頼枠を変えず、翌日以降の通常抽選に加わります。

## 日数と採集回数

1日目・採集残り3回から開始します。採集1回で残り回数を1消費し、0回になると採集ボタンが無効になります。加工・在庫確認・依頼確認・納品は回数を消費しません。

工房の「今日は休む」で確認画面を開き、「休んで次の日へ」で翌日・残り3回になります。「まだ作業する」またはEscapeキーでは何も変わりません。残り回数があっても休めますが、翌日への持ち越しはありません。

日付は休む操作でだけ進み、現実の時刻とは連動しません。依頼期限・日数制限・ペナルティはありません。在庫・依頼進行は翌日も引き継ぎます。

日数（day）と残り採集回数（gathersLeft）は既存の保存キーへ一緒に保存します。旧セーブにこの情報がない場合は1日目・3回を補い、既存の在庫・依頼進行を保持します。0回もそのまま復元され、再読み込みで回復することはありません。

## ファイル構成

- `index.html`：画面の土台
- `style.css`：スマホ対応のレイアウトと仮UI（画像・外部フォントなし）
- `game.js`：素材、レシピ、固定・日常依頼、採集・加工・納品・翌日更新・図鑑記録のルール
- `app.js`：6画面の表示、操作、localStorage保存
- `test-game.cjs`：基本ループと消費処理の確認（`node test-game.cjs`）
- `test-app.cjs`：依頼画面・クリック処理・段階解放・日常依頼・保存復元の確認（`node test-app.cjs`）

## 調整と保存

素材・レシピ・依頼は `game.js` の定義で変更できます。加工の出力は1回につき1個です。
追加した複数素材レシピは `inputs` に素材IDと必要数を定義しています。既存の単一素材レシピも同じ加工処理で扱います。
保存キーは以前と同じです。旧セーブの在庫・達成状況を引き継ぎ、新しい在庫は0から開始します。最初の3件を達成済みなら、第2段階を自動で解放します。新在庫・追加依頼の達成状況・解放段階（`unlockedStage`）を保存し、読み込み時は最初の3件の達成状況から解放段階を整合させます。
進行状況は操作ごとにブラウザのlocalStorage（キー `mioverse-craft-v1`）へ自動保存します。同じブラウザ・同じ配信元で再開できます。別端末との同期はありません。ブラウザのデータ消去で保存内容も消えます。ファイル直接起動時やプライベートモードなどで保存できない場合は画面に表示します。安定した保存には HTTP(S) 配信を推奨します。複数タブで同時に遊ぶと最後の保存が優先されるため、1つのタブで遊んでください。

GitHub Pagesではこのフォルダのファイルをリポジトリへ置き、Settings → Pagesで対象ブランチのルートを公開対象にしてください。

## 最初からテストする場合

完成品を作るだけでは依頼は達成されません。3人とも依頼画面の「1個届ける」を押すと、完成品を1個消費して達成します。以前に納品した保存データは、更新後も達成済みとして復元されます。

初期化する場合は、ゲームを開いているブラウザの開発者ツール（F12）の Console で次を実行します。このゲームの在庫・依頼達成状況が消えるので、最初からやり直したい場合だけ実行してください。他のゲームの保存データは消しません。他に開いているこのゲームのタブは先に閉じてください。

```js
localStorage.removeItem('mioverse-craft-v1');
location.reload();
```

画面操作・保存の回帰テスト：`node test-app.cjs`（ブラウザの保存データを変更せず、メモリ上の仮画面・保存領域で検証）。

農園・料理・天候・季節・好感度・ストーリー・アクションなどは実装していません。
